# App use, workspace pins, and bar layout

## Spotlight

The empty query lists the most recently used/launched apps first. Typing filters the installed-app catalog, then sorts matches by last use, relevance and name. Successful Spotlight launches and foreground activation of recognized apps update `spotlight-history.json` beside the installed helper. Packaged app IDs, workspace process rules and cached executable metadata identify apps. Unknown processes are ignored. No window titles, typed queries or browsing history are saved.

Search and arrow navigation work from memory. History writes are debounced and atomically merged across helpers. Opening search refreshes the catalog/history; arrow presses neither scan apps nor change the list order. History starts learning after this update; old activity cannot be reconstructed. Delete `spotlight-history.json` while helpers are stopped to reset it.

Research: [PowerToys History](https://github.com/microsoft/PowerToys/blob/main/src/modules/launcher/Plugins/Microsoft.PowerToys.Run.Plugin.History/Main.cs) sorts by last selection and filters history by query. [Flow Launcher MainViewModel](https://github.com/Flow-Launcher/Flow.Launcher/blob/dev/Flow.Launcher/ViewModel/MainViewModel.cs) combines relevance with selection counts and guards asynchronous results with cancellation tokens. Our implementation uses recency rather than a frequency bonus, per the requested behavior. Future file/web providers should use cancellation and query-generation IDs so stale results cannot replace newer ones. Optional query-specific favorites and a clear-history action are useful later additions.

## Workspaces

`workspaces.json` in the install folder (`%USERPROFILE%\.glzr\zebar\nord-rice`) is the single definition of every workspace. The installer keeps your copy; the repo's copy is only the default for new installs.

```json
{ "name": "5", "label": "Terminal", "monitor": 1, "apps": [
  { "id": "termius", "catalogPattern": "^Termius$", "processPattern": "^Termius$" }
] }
```

| Field | Meaning |
|---|---|
| `name` | GlazeWM workspace name (`1`–`9`, `0` match the Alt+number keys). File order is GlazeWM's order. |
| `label` | Text under the card in the Alt switcher. |
| `monitor` | Monitor the workspace belongs to, starting at 1. |
| `keepAlive` | Optional. Keep the workspace even when empty. Defaults to true when it has apps. |
| `apps` | Default apps: `id` (unique), `catalogPattern` (Start menu name, for the taskbar pin and launching), `processPattern`, optional `titlePattern`. Patterns are case-insensitive regexes; anchor them. |

What reads it:

- **Bar taskbar pins** and the always-shown workspaces refresh within a few seconds of saving. Only installed apps are pinned.
- **Alt switcher labels** update as soon as you save.
- **GlazeWM** (workspace list and app rules) is regenerated by the control center about a second after you save, and again whenever it starts. The bar's rules button turns the app rules on or off. The generated parts of GlazeWM's config are marked; edits there are replaced. During lock-in, changes wait until it ends.

An invalid file (bad JSON, duplicate names or ids, bad regex) is rejected: GlazeWM keeps its last config and the reason is written to `workspace-sync.log` in the install folder. The bar and switcher keep their last good copy too.

## Workspace app pins

The rules button controls automatic placement; it does not hide pins.

Closed apps are grey; clicking launches the catalog entry. Apps open on another workspace retain color with a dashed border; clicking focuses their existing window there. Other windows in the current workspace remain on the strip. Right-click a running icon for Focus/End task. A repeated launch is briefly debounced; locked-in restrictions still apply.

## Rice → Widgets & layout

Click a name to toggle visibility. Up/down change its order; the horizontal arrow moves it to the other side. Apply saves visibility and order together to `rice-widgets.json`; all monitor bars pick it up without restarting. Discard restores the last saved settings. Reset layout restores arrangement, preserving visibility. A `.previous` file keeps the preceding saved config.

The centered clock and the reserved workspace task strip stay fixed. The left lane keeps its 34vw endpoint (clamped safely on narrower displays). Crowded side lanes scroll horizontally instead of overlapping the clock or task strip. Disabled/hidden widgets retain their saved position. Invalid/duplicate entries are repaired and newly introduced widgets are appended to their default side. The older Nord preset editor no longer controls the GlazeWM bar arrangement; use the Rice tab.
