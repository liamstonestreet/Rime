# Shared theme transitions

Wallpaper palettes use one UTC start timestamp and cosine easing curve across the desktop fade, Zebar, CC, workspace and wallpaper indicators, Spotlight, screen frames and window borders. Indicator wallpaper switches use a shared 700 ms fade; other theme changes use 450 ms. Rice's animation speed scales these, capped at 1500 ms. Motion off and Windows reduced motion settle immediately.

Palette extraction and per-monitor frost rendering finish before publication. Frost images are staged, then committed together with an atomic transition descriptor (`theme-transition.json`). A 180 ms lead gives bar pushes and native file watchers time to receive the same timeline. Late receivers join its current position. Duplicate snapshots do not restart it; older snapshots are rejected. Superseded background requests do not publish obsolete themes.

Zebar animates palette variables locally with requestAnimationFrame, avoiding competing per-widget CSS color transitions. Native theme brushes and gradient stops retain their references and update on a finite dispatcher clock. Frost images crossfade on the same clock; old image layers are released afterward. No per-frame image decoding, IPC, config reload or visual-tree rebuild is needed. Hidden workspace indicators apply the current transition position when opened.

GlazeWM's managed windows receive DWM border colors on the shared clock when borders are enabled. Final colors are saved without reloading GlazeWM, issuing focus commands or moving the cursor. Small, finite focus/show handlers retain the live colors when GlazeWM reapplies its window effects; new managed windows are discovered off the UI thread. DWM border colors require Windows support. OS composition and separate processes can differ slightly at frame boundaries; this is a shared timeline, not a cross-process rendering barrier.

During a wallpaper switch the old desktop remains visible while images, palette and frost are prepared. All covers are painted at zero opacity before the shared timestamp is published. Desktop covers use that exact clock, including the initial lead period, rather than an independent stopwatch. Only after the combined fade completes does Windows set the real wallpaper behind the opaque covers. Appearance polling is held until this commit finishes, preventing the still-old desktop path from restoring old colors mid-fade. Preparation failures leave the old wallpaper in place; commit failures release the gate and refresh from the actual desktop.

The existing serialized preview-preparation worker also warms the selected wallpaper's palette and frost while browsing. Only the most recent palette and frost bundle are retained. A matching commit reuses that prepared frost instead of rendering it again; background polling may discard a stale speculative bundle safely. Preparation never publishes preview colors or changes the desktop.

Checks: `node checks/theme-sync/check.mjs`, `node checks/shell-polish/check.mjs`, native `build.ps1 -Checks` / `checks\CenterChecks.exe`, and the workspace indicator's `--check-styles`. Checks use synthetic palettes/images and do not change live wallpaper or app borders.
